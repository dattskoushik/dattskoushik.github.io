How I Think About Data Systems

Reliability & Idempotency

Systems fail. I design pipelines where "retry until success" is safe because operations are idempotent. Data integrity must survive network drops and process crashes.

Data Quality

Bad data is worse than no data. I enforce strict schema validation, null checks, and referential integrity before data reaches the gold tier or analytical warehouse.

Simplicity & Maintainability

I avoid unnecessary architectural complexity. Using the right tool often means using the simpler tool. Code and schemas must remain readable and understandable by the entire team.

> SQL: Rolling Averages (CTE)

View on GitHub → 
WITH daily_sales AS (
    SELECT
        date_trunc('day', created_at) AS sale_date,
        SUM(amount) as total_amount
    FROM sales_fact
    WHERE created_at >= current_date - interval '30 days'
    GROUP BY 1
)
SELECT
    sale_date,
    total_amount,
    AVG(total_amount) OVER (
        ORDER BY sale_date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) as rolling_7d_avg
FROM daily_sales;

def load_data_idempotent(df: pd.DataFrame,
                         table_name: str,
                         engine: Engine) -> None:
    """Upserts data ensuring no duplicates on retry."""
    try:
        with engine.begin() as conn:
            # Create temporary staging table
            df.to_sql('temp_stage', conn, if_exists='replace', index=False)

            # Perform upsert (PostgreSQL specific)
            upsert_sql = f"""
                INSERT INTO {table_name}
                SELECT * FROM temp_stage
                ON CONFLICT (id) DO UPDATE
                SET updated_at = EXCLUDED.updated_at,
                    value = EXCLUDED.value;
            """
            conn.execute(text(upsert_sql))
    except Exception as e:
        logger.error(f"Load failed: {e}")
        raise
